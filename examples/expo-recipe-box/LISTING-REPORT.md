## Dogfooding findings (fed back to the skill/flows)
1. **Maestro device selection** — on a machine with both an Android emulator and iOS
   simulators running, Maestro defaults to the first device (Android). The driver must
   pass `--device <udid|serial>`. → documented in `references/driving/maestro.md`.
2. **`clearState` vs. Expo dev-client** — `launchApp: clearState: true` wipes the
   dev-client's saved Metro URL, so a debug build can't reload its JS and flows fail.
   Capture from a **release** build (clearState fine there, no dev menu). → documented
   in `references/driving/maestro.md`.
3. **Deep-linking into a running app stacks navigation** — relaunch + a single deep
   link per screen gives clean back-stack labels; chaining deep links shows stale ones.
4. **Play aspect-ratio limit** — the Pixel 8 captures at 1080×2400 (2.22:1), which
   exceeds Google Play's **2:1** max aspect ratio. The Validate step cropped each to the
   recommended **1080×1920** (16:9); our screens' content sits in the top region, so no
   content was lost. A real run should either target a ≤2:1 device profile or crop.

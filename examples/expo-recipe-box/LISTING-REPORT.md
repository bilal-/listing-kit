## Dogfooding findings (fed back to the skill/flows)
1. **Maestro device selection** — on a machine with both an Android emulator and iOS
   simulators running, Maestro defaults to the first device (Android). The driver
   must pass `--device <udid>`. (Documenting in `references/driving/maestro.md`.)
2. **`clearState` vs. Expo dev-client** — `launchApp: clearState: true` wipes the
   dev-client's saved Metro URL, so a debug build can't reload its JS and flows fail.
   It's correct for **release/standalone** builds. Store screenshots should be
   captured from a **release** build (also avoids the dev menu) — the flows' clearState
   is fine there.
3. **Deep-linking into a running app stacks navigation** — capturing each screen via a
   single relaunch + one deep link gives clean back-stack labels; chaining deep links
   onto a live stack shows stale back titles.
